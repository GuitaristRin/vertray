# 数据分层

本目录的划分不是整理偏好，而是许可边界。混放会让两套条款同时失效。

| 目录 | 内容 | 许可 | 可否主张保留所有权利 |
|---|---|---|---|
| `base/` | 派生自 OpenStreetMap 的底图几何、周边道路与用地 | ODbL 1.0 | **否** |
| `survey/` | 实地采集与核对所得：门位、门向、共享门厅、连接体、桥梁、通行限制 | PolyForm Noncommercial 1.0.0 | 是 |
| `render/` | 由两者生成的产物（SVG 分档），不手工编辑 | 随源 | 产物随其来源 |

实际文件与分类依据见 [ADR 0002 · 数据布局](../docs/decisions/0002-data-layout.md)。

## 判据

一条数据属于哪一层，看它的**来源**，不看它长什么样：

- 来自公开数据集、且该数据集有署名或传染性条款 → `base/`
- 由人到现场查看、测量、记录所得 → `survey/`
- 由前两者计算生成 → `render/`，且必须能追溯回来源

同一文件不得同时承载两类数据。需要并列时，放在不同文件、不同字段组，并在生成报告中分别记录来源。

## 为什么不能合并

ODbL 要求衍生数据库继续以 ODbL 提供。若把实测门位并入 OSM 派生文件，整份数据即成为衍生数据库，实测部分也被 ODbL 覆盖，Noncommercial 条款在此失效；反过来，若对 `base/` 主张保留所有权利，则违反来源方的条件。

两边都会输，所以分开放。

## 采集与核验

`survey/` 的每一项须同时给出：

- 来源（现场观察 / 用户说明 / 导览图 / 卫星图）
- 核验日期
- 覆盖范围与未确认项

只记录观察到的事实，不记录推断。「这栋楼应该朝北」不是数据，「15 号楼北门朝北，2026-10-21 现场确认」才是。
