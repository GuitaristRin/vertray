# 回流指南

> 一次到过现场的人，比十次看地图的人更接近事实。

回流面向所有使用者：提交实地修正、报告配准问题、纠正文档、补上未知的门位。使用 vertray 不附带必须贡献代码的条件，本文不增加许可之外的义务。

## Ⅰ · 何种所得值得回流

| 所得 | 建议去处 | 所需依据 |
|---|---|---|
| 门位、门向、共享门厅、连接体的实地修正 | 上游提交，附现场依据 | 位置、日期、观察方式、覆盖范围、未确认项 |
| 配准或比例错误 | 上游 Issue | 哪一档、何处偏移、比对图或控制点 |
| 通行限制（禁行、施工、单向） | 上游提交，注明时效 | 现场所见、生效时间、是否长期 |
| 建筑别名、分区、教室编号规则 | 上游提交 | 来源（导览图、课表、现场指示牌） |
| 文档歧义、易误用处 | 文档 Issue 或 PR | 误解发生的场景 |
| 宿主侧渲染与交互经验 | 先留调用方 | 场景、选择依据、验证范围 |
| 新能力（室内、人流、到站） | 先讨论来源与核验方式 | 可复现场景、数据来自何处 |

**通用者宜回流，专用者先留调用方。** 第二个独立校园是评估通用性的有力证据，但不因此自动纳入。

## Ⅱ · 不回流的内容

以下即使看起来有用，也不接收：

- 从商业地图截图描出来、来源不可署名的几何
- 未到现场的推测：「按对称应该还有一扇门」
- 含个人轨迹、可定位到具体个人的采集记录
- 违反来源条款导出的数据集

## Ⅲ · 最小报告格式

```text
类型：实地修正 / 配准问题 / 文档 / 使用经验 / 能力提议。
地点：校区、建筑或路段；必要时给坐标。
事实：观察到什么；何时；以何种方式（步行、骑行、停留、指示牌）。
依据：现场照片、导览图、课表或公开数据；可公开则附，不可公开则说明。
范围：覆盖到哪里；哪里没看；什么条件下不成立。
建议：数据修正、文档澄清或待采集。
```

不适用的字段可省略；**「范围」不建议省略**，它是判断能否参与导航的唯一依据。

## Ⅳ · 边界

- 提交即表示你同意该项内容按本仓条款发布；若来自 ODbL 数据，则须放入资产仓的 `layers/00-osm/` 并保留署名。
- 不接受不明确来源的贡献。来源不清的数据无法被复核，也就无法被信任。
- 已合并的修正不会因为提交者退出而被回收；但署名与记录保留在提交历史中。

## Ⅴ · 参与的意义

回流的目的不是攒贡献数，而是让下一次有人站在同一个路口时，不必再猜。
