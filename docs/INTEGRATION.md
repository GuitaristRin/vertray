# 调用指南

> 引擎供其形，宿主定其用。

本文面向接入 vertray 的宿主项目。接口细节随 v0.1 实现固定，本文先定边界与流程，不承诺尚未存在的命令。

## ⅰ · 接入方式

| 方式 | 适用 | 代价 |
|---|---|---|
| git submodule | 需要产物与数据同版本可追溯；宿主愿意承担 `--recursive` 与 CI 授权 | 克隆与构建配置变复杂，版本指针需人工推进 |
| git 依赖 / 私有包 | 前端项目、单一构建链 | 数据与代码同仓发布时颗粒度较粗 |
| vendored 副本 | 一次性实验 | 失去上游，实地修正难以回流 |

选择由宿主决定，不因接入方式获得额外授权。版本必须固定到提交或发布标签，并在此处记录，避免以最新文档推断旧版行为。

## ⅱ · 职责边界

**引擎负责：**

- 事实层数据模型与校验（来源、核验状态、配准）
- 分层 SVG 与构建报告的生成
- 建筑、入口、接近点与连通关系的查询接口

**宿主负责：**

- 渲染、手势、缩放、深链接与可访问性
- 路线展示、时间预估与出行方式选择
- 与课表、天气、校车等外部能力的组合

引擎不接管宿主的帧循环与交互。宿主持有状态、决定何时请求重算。

## ⅲ · 构建与验证

生成流程按阶段划分，任一阶段失败即整体失败，不以部分产物上线：

1. **读入**：底图来源快照、实测数据、配准参数。
2. **校验**：来源字段齐全、配准与快照匹配、两类数据未混装。
3. **生成**：按缩放档输出分层 SVG，写出构建报告（输入哈希、要素计数、输出统计）。
4. **检查**：产物的结构、尺寸与地理范围，以及宿主页面在目标视口下的表现。

生成必须是幂等的：同一输入应得到逐字节相同的产物；否则说明有未被记录的输入。

## ⅳ · 让 Agent 自然沿用

依赖中的文档不一定被调用方 Agent 自动发现。在调用方的项目指引中放置一次可达入口，后续地图任务沿此入口工作：

```text
本项目使用 vertray 构建校园地图。
地图任务先读 vertray 的 docs/README.md，并按其中指引阅读正典与调用指南。
几何必须带来源与核验状态；未核验者画虚线或干脆不画。
任务完成时简述数据来源、核验方式与验证范围；可复用的修正按 BACKFLOW.md 整理。
```

无需为每个地图任务重复整套规则，也无需仅为使用 vertray 修改其上游。

## ⅴ · 验证清单

接入完成后至少确认：

- [ ] 三档缩放的配准一致，切换时地物不漂移
- [ ] 未核对的门位以虚线或缺失呈现，未被补全为实线
- [ ] 空白区域不被理解为「没有」
- [ ] 产物中保留 OpenStreetMap / ODbL 署名
- [ ] 构建可离线重复，产物不因重跑而变动
- [ ] 数据来源与核验日期可被查出

未通过项不得以「后续再补」进入正式环境——地图的错误会以用户走错路的方式结算。
