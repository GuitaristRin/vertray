# ADR 0001 · 语言策略

- 状态：已采纳（2026-10-22）
- 决定：运行时核心用 TypeScript；构建管线用 Python；采集器用 Kotlin；Rust 与 C# 暂不引入，条件见 Ⅴ。

## Ⅰ · 问题

vertray 要在浏览器、Android、将来的桌面上跑。作者的母语栈是 Kotlin（安卓）、Rust（Linux）、C#（Windows），三者与宿主 portal-web 的 TypeScript 都不重合。若按「一次编写、多端复用」的直觉，应选 Rust 编译到 WASM + FFI；若按现有消费者，应选 TypeScript。两条路都能自圆其说，所以需要判据，而不是偏好。

## Ⅱ · 判据

按权重排序：

1. **谁是消费者。** 今天只有一个仍在使用的宿主：portal-web（Web + APK WebView）。
2. **算力是不是约束。** 校区规模：59 个特征、200 个入口、路径图节点三位数。命中测试与最短路在 JS 里是微秒级。
3. **契约能否共享。** 数据形状由宿主类型系统消费；两套类型定义必然漂移。
4. **能否被 Agent 读懂并正确扩展。** 本仓的长期形态是「文档 + 数据纪律」，不是黑盒二进制。

四条都指向 TypeScript。Rust/WASM 的优势（速度、跨端复用）在 1、2 上换不到任何东西，在 3、4 上是负分。

## Ⅲ · 决定

| 层 | 语言 | 理由 |
|---|---|---|
| 运行时核心（`src/`） | TypeScript | 与宿主同类型系统；零运行时依赖；可被 Agent 直接审阅 |
| 构建管线（`tools/`） | Python | stdlib 足够解析 SVG/JSON；离线自足；已有实现验证过 |
| 采集器（`tools/collector-android/`） | Kotlin | 仅安卓可用，无跨端复用；作者母语；现有 Java 可用，不提前重写 |
| 一致性夹具（`test/fixtures/`） | JSON | 语言中立，供将来任何实现做对拍 |

## Ⅳ · 让语言选择可逆

决定本身不如「可逆」重要。核心被约束成：

- 纯函数：输入普通对象，输出普通对象。
- 不触碰 DOM、`fetch`、`fs`、时钟、随机数。
- 数据以 JSON 跨边界，不传类实例。
- 行为写进夹具：同一输入，任何语言实现都应给出同一输出。

满足这四条，换语言只是重写一遍函数体，契约不动。若核心写成「一启动就接管全局状态」，语言就被锁死了。

## Ⅴ · Rust 与 C# 的引入条件

**Rust** 在下列任一条件成立时引入，且以现有 TS 为参考实现，用夹具对拍：

- 出现第二种宿主（原生桌面或非 WebView 安卓）且不愿维护第二实现；
- 数据规模跨过十万级节点，路径查询成为交互瓶颈（届时先测，不先猜）；
- 需要与 Sokuou / Zethora 同进程调用。

**C#** 仅在出现 Windows 原生桌面宿主时考虑。当前无此计划，不预留抽象层——为不存在的宿主做设计，成本立刻发生，收益永不兑现。

## Ⅵ · 非目标

- 不做通用 GIS：坐标系转换、投影族、栅格处理都不在范围内。
- 不做瓦片服务：产物是静态 SVG 分档，按需再议。
- 不为「可能的跨端」写胶水层；跨端是结果，不是预算项。
