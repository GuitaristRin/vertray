# vertray 文档库

> 正典明其意，指南致其用，回流促其准。

本文档库面向所有接入 vertray 的开发者与 Agent，不以特定应用、框架或仓库为前提。目标是让调用者自然沿用 vertray 的数据纪律，并把真实使用中的实地修正带回上游。

## 从何处读起

| 所求 | 文档 | 读后应知 |
|---|---|---|
| 理解 vertray 何为地图 | [MAP.md](MAP.md) · 正典 | 三层结构、来源与核验状态、不变量、入口模型、失败模式 |
| 接入自己的项目 | [INTEGRATION.md](INTEGRATION.md) · 调用指南 | 接入方式、职责边界、构建阶段、验证清单 |
| 提交实地发现或修正 | [BACKFLOW.md](BACKFLOW.md) · 回流指南 | 何种所得值得回流、以何证据、范围如何写 |
| 修改本仓 | [../AGENTS.md](../AGENTS.md) · 工作流守则 | 数据纪律、代码放置、提交约定 |
| 资产分层与许可 | `vertray-assets` 仓的 `README.md` · 私有 | 哪份数据属哪套条款，为何不能合并 |
| 语言与结构依据 | [decisions/](decisions/) · 设计决策 | 为什么是 TypeScript、为什么分引擎/资产/实例 |

初次接入，依次读正典与调用指南；遇到实地修正，再按回流指南整理。

## 文档各司其职

- **正典**定概念与契约。语义有变，随代码一同修订。
- **调用指南**给默认流程。宿主可据交互、可访问性与品牌作选择，并留下理由。
- **回流指南**连接现场与上游。Issue、使用报告、数据修正与文档 PR 均为有效回流。
- **本仓守则**约束在本仓的修改，不自动成为所有消费方仓库的制度。
- **数据说明**是许可边界的正文，不是补充材料。

正典描述预期契约；实现与构建报告反映当前实际行为。二者冲突时记录差异并修正，不可假定尚未实现的能力已经存在。

## 让 Agent 自然沿用

依赖库中的文档不一定会被调用方 Agent 自动发现。在调用方的 `AGENTS.md`、`CLAUDE.md` 或等效项目指引中放置一次可达的入口即可：

```text
本项目使用 vertray 构建校园地图。地图任务先读 vertray 的 docs/MAP.md 与 docs/INTEGRATION.md。
几何必须带来源与核验状态；未核验者画虚线或干脆不画，未知不得留白当作没有。
任务完成时，简述数据来源、核验方式、覆盖范围；可复用的实地修正按 docs/BACKFLOW.md 整理。
```

将路径替换为调用方实际可访问的位置；未将源码置于工作区时，可链接到所用版本的仓库文档。记录所用版本或提交，避免拿最新版文档推断旧版接口。
