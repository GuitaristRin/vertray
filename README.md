# vertray（矢·迹）

> 地图不是一张图，而是一组关于空间的可核验陈述。

vertray 是一个**可核验的校园矢量地图引擎**：把实地记录、公开来源与建筑结构整理成带来源与核验状态的空间数据，生成分层 SVG 产物，并向宿主提供入口、连通与查询能力。

`记录 → 空间结构 → 分档产物 → 渲染`

名字由 **vert**（vertex，顶点）与 **ray**（射线）拼成：可去的地方是顶点，从顶点出发的视线是路。中文作「矢·迹」——矢量是形，轨迹是据。地图的职责不是把校园画好看，而是回答「我从这里能不能走到那里、凭什么这么认为」。

## 定位

- **引擎，不是应用。** 本仓不含宿主的路由、组件与交互。渲染、手势、深链接归调用方。
- **数据优先于绘制。** 图的样式可以换，来源与核验状态不能丢。
- **离线可重复。** 给定同一输入，生成同一产物；不依赖网络、第三方瓦片服务或专有工具链。
- **未知保持未知。** 未核验的通行权限、室内结构、门位，以「未知」表达，不以空白或猜测填充。

当前首个实例是齐鲁工业大学长清校区，数据与管线自 `portal-web` 的地图模块迁出，存放在私有资产仓；本仓只保留合成示例。

## 为什么不是 MIT

判据不是「我喜不喜欢限制」，而是**这个仓有没有不可替代的现场数据**。

Sokuou 是纯原语，没有现场劳动、没有第三方数据边界，因此 MIT 最合适。vertray 的几何背后是实地采集：门在哪一侧、两栋楼如何共用门厅、哪条路禁行。这类投入一旦被无偿商业使用，就再也收不回来，所以授权必须留出口子，但不应留成死结。

## 三层

| 层 | 仓 | 内容 | 许可 |
|---|---|---|---|
| 引擎 | 本仓 | 模型、校验、查询、渲染模型、构建器 | [PolyForm Noncommercial 1.0.0](LICENSE) |
| 资产 | [vertray-assets](https://github.com/GuitaristRin/vertray-assets)（私有） | 分层数据、权属声明、实例配置 | 逐层：ODbL / 本仓条款 |
| 实例 | 构建产物 | 渲染模型与 SVG 分档，锁内容哈希 | 随其来源层 |

**本仓不含真实校园数据。** 测试与演示使用 [examples/toy-campus](examples/toy-campus/)，一份虚构的合成校区。

方向只有一条：引擎 + 资产 → 实例。实例不被手改，资产不被宿主直读。

### 使用场景

PolyForm Noncommercial 的判定对下面几种情况是清楚的：

| 使用方式 | 是否免费 | 依据 |
|---|---|---|
| 学生学习、研究、个人项目 | 是 | Personal Uses |
| 学校、公立机构自用（含经费来源为企业的项目） | 是 | Noncommercial Organizations |
| 企业承接交付、对外服务、随产品收费 | 否，需商业授权 | 超出 Noncommercial Purposes |

学校自用不受资助来源影响，这一条是条款明文，不是解释。企业与学校之间是两件事。

## 当前状态

**v0.2 — 引擎、资产、实例三层分离。**

- 引擎：`src/` 提供实例加载、数据合成、入口可信度、最近可达入口、平面几何与分层校验；纯函数、零运行时依赖。
- 资产：已迁至独立私有仓，按 `00-osm` / `10-survey` 分层，逐层声明来源、权属、劳动与许可。
- 测试：22 项，全部基于合成示例，引擎仓不含真实校园数据。

尚未迁入：SVG 生成管线（仍在 `portal-web`）、采集器、宿主接回。

## 让 Agent 自然沿用

在调用方的 `AGENTS.md`、`CLAUDE.md` 或等效项目指引中放置一次可达的入口即可：

```text
本项目使用 vertray 构建校园地图。地图任务先读 vertray 的 docs/README.md，
并按其中指引阅读正典与调用指南。
空间数据必须带来源与核验状态；未核验的几何不得画成事实。
任务完成时，简述数据来源、核验方式与验证范围；可复用的实地修正按 BACKFLOW.md 整理。
```

记录所用版本或提交，避免拿最新文档推断旧版接口。使用 vertray 不以贡献代码为前提。
